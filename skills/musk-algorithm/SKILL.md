# 五步流程审查

方法来源是马斯克在 [Everyday Astronaut 2021 年采访](https://everydayastronaut.com/starbase-tour-and-interview-with-elon-musk/)中讲述的工程流程。本项目编写的是面向人机协作的审查封装，不声称发明这套方法，也不包含第三方 Skill 的正文。

只在用户请求审查或优化时应用。已有信息足够就直接审查；缺少会改变判断的上下文才追问。评估请求只交付建议，实施授权不包含删除受保护内容或扩大项目范围。

1. **核对必要需求**：列出对象的实际组成、用户明确保留项、依赖和承诺。把已证实的必要需求与待验证假设分开。提出者的身份本身不证明需求正确，也不成为删掉它的理由。
2. **评估删减**：指出无必要或重复的部分及后果；不要为了凑百分比删除。只在已有授权内实施可逆修改，保留用户的其他改动；不可逆变更先交付可审查的具体方案。
3. **简化保留项**：比较能够满足必要需求的合并或替代方式。不要只减少表面步骤，却把工作或风险转给用户；有不确定依赖就注明，不能记作优化成功。
4. **缩短反馈**：用实际观测定位瓶颈，估计收益时说明依据；验证与改动风险相称。没有数据时给验证办法，不编造提速比例。
5. **判断是否自动化并交付**：只考虑已经跑通且有重复价值的流程。自动化需要新的访问、费用或外发时沿用对应授权边界。说明建议或实际改动、保留理由、验证结果和未决项；当前任务达到要求后结束，不自动增加审查轮次或另建定时任务。

公开版验证包含受限案例走查；不把采用这五步等同于必然提高效率。
