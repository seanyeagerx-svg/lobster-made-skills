# 多模型对比蒸馏

1. **确定比较问题**：确认同一任务、已有模型输出、评价目标及具体决策点；需要新模型调用时沿用用户授权、资料可共享范围和可用工具。完成标准：样本输入可比，每份输出标明模型与来源。
2. **定位分歧与共识**：提取各输出在决策点上的不同假设、方法和结论；把共同事实与仍需验证的共识分开。完成标准：每个分歧有对应原文，共识没有被当成正确性证明。
3. **检查模型倾向与缺席项**：从本批样本归纳重复动作和所有样本遗漏的方向；把倾向标为本批观察，避免永久模型标签。完成标准：倾向和遗漏均可回指样本，推测单独标记。
4. **收集选择与拒绝理由**：捕获用户具体偏好、否定边界及适用项目；用户明确要求排序时按已定标准给排序及理由。完成标准：偏好有来源和范围，AI 判断与用户选择分别署明。
5. **交叉质疑**：任务需要时将某份输出交另一可用模型质疑，核验批评所依据的事实和弱点，再修订候选。完成标准：每条采纳的批评有证据，或列为待检假设；模型同意本身不算验证。
6. **交付并保存适用结论**：给出作品/任务答案及分歧、选择依据；已有获准的项目记录中保存可复用偏好，定期重测过时约束。完成标准：当前任务有可用产物，偏好记录带项目和来源，不把会话历史写进技能文件。
