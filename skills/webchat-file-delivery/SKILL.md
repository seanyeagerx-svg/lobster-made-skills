# WebChat 文件投递

1. **核对交付对象**：确认当前会话为 WebChat、文件路径可读且内容为本次产物；把文件名与用户要原件/可读版的要求对齐。完成标准：已选定实际存在的文件与目标会话。
2. **提交附件**：使用当前通道支持的附件机制；使用 `MEDIA:` 时，在同一条交付回复中写出 `MEDIA:<实际路径>`，输出前逐项核对承诺的附件均已附上。不同客户端对单文件、多文件、ZIP 与 `MEDIA:` 的支持可能不同；历史单次成功不作为本次能力证明。完成标准：本次回复确实携带文件引用；状态只记「已提交，送达待确认」。
3. **按失败证据选格式**：若当前客户端确实拒绝 HTML，使用 Python `zipfile` 打包原件；用户需要可读正文时另存 Markdown，检查正文提取完整性后提供。ZIP 是候选替代格式，仍需步骤 4 验证。完成标准：替代文件可打开、内容正确且已按步骤 2 提交，或格式问题已明确。
4. **读取接收端证据**：核对目标会话里与本次文件匹配的附件事件/卡片及可打开或下载的结果，或取得用户确认收到并能打开。日志只有 accepted、queued、send success 或 MEDIA 文本不足以证明文件可用；泛称「投递成功」也须核实其含义和文件、会话标识。完成标准：证据包含本次文件、目标会话和接收端可用结果才报告「已送达」；否则明确「已提交，送达未确认」，保留待确认状态并避免重复盲发。

飞书属于另一通道，使用当前环境中已获授权的飞书工具，并按其通道证据验证；本技能不内置飞书发送能力。
