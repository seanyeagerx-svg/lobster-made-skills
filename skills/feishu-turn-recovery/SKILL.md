# 飞书漏答恢复

只处理用户要求核对的会话和时间段；一句普通问候不触发历史调查。补答沿用本次会话的回复授权，读取日志不新增发送其他消息的权限。

1. **确定待核对区间**：从当前会话与日志确认 sessionKey、用户消息时间和异常时间；出现 `per-chat task exceeded 300000ms cap ... evicting` 时记录该次日志的阈值。当前安装版本的 docs 的 `channels/feishu.md`、`plugins/reference/feishu.md` 未规定统一 300s turn cap；`concepts/agent-loop.md` 区分运行预算与 provider idle watchdog，不能把后者的 300s 当飞书上限。完成标准：已有具体会话、时间区间和实际异常证据，或明确仅为疑似漏答。
2. **建立未答清单**：用 `sessions_history` 读取该会话，按消息内容关联后续回复，而非把任意一条 assistant 消息当作前面全部已答。核对历史截断、活跃/排队 turn 和实际投递结果，避免重复回答仍在处理的消息。完成标准：每条用户请求标为已答、处理中、未答或证据不足。
3. **恢复结论并补答**：对未答请求读取失败 turn 已完成的工具结果和产物，验证后回复；已有发送回执先核实，避免重放有副作用的动作。缺失媒体说明具体缺口，再请求必要材料。完成标准：每条未答请求均有相关回复或明确的材料/执行阻塞，发送和用户可见状态分别记录。
4. **保留可恢复交付物**：长任务在授权的工作记录中保存结果与证据位置，再发送简短交付。完成标准：后续 turn 可定位已完成动作、待答消息及未确认投递，不依赖失败 turn 的记忆。
